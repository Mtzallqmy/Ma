Neon هي السحابة الرسمية الوحيدة:
1. Neon PostgreSQL: metadata/articles/source registry/content versions/pack manifests and review statuses.
2. Neon Object Storage: photos, diagrams, GLB/GLTF, downloadable JSON packs, licensed assets.
3. Neon Functions: HTTPS API endpoints connecting Android clients to PostgreSQL and Storage; never connect Android directly to database or S3 with secret credentials.

اعمل أولًا على مسار Android Client آمن، لا تتطلب هذه المرحلة تشغيل خادم داخل AI Studio Android لأنه غير مدعوم. عند وجود أدوات Neon الخارجية المصرح بها: أنشئ مشروعًا/فرعًا تجريبيًا منفصلًا باسم واضح، تحقق من المنطقة المدعومة لـ Object Storage + Functions، أنشئ ترحيلات SQL ودوال API ومخزنًا تجريبيًا وأجر اختبار استدعاء حقيقي. احفظ أدلة النجاح. إن لم تتوفر هذه الأدوات: قدم SQL وOpenAPI ووصف endpoint وعينات Neon Functions قابلة للنشر في بيئة مناسبة خارج مشروع أندرويد، واجعل وضع شبكة الاختبار قابلًا للاستخدام لاحقًا دون إعادة كتابة واجهات Android.

- عند فتح محتوى ثبت محليًا، يفتح فورًا دون شبكة ولا يستدعي API بصورة إجبارية.
- حزم النصوص مستقلة عن حزم الصور وعن 3D، ويمكن تنزيل نموذج واحد فقط دون الجهاز بالكامل.
- إظهار «تحتاج حزمة مصاحبة بحجم X» قبل تنزيل تبعية إضافية؛ لا تحميل خفي.

Contract للحزمة:
packId, version, scopeType, scopeId, titleAr, titleEn, language,
contentKind, quality, schemaVersion, minAppVersion, sizeBytes,
files: [{path, contentType, sizeBytes, sha256, assetId}],
dependencies[], sources[], license, attribution, publishedAt.

فترات التنزيل: queued/running/paused/failed/completed/updateAvailable/notDownloaded. أظهر حجم التحميل الحقيقي وتقدم bytes إن وُجد. إلغاء/إعادة محاولة/استئناف على مستوى الملف، وHTTP Range فقط بعد التحقق من دعمه. قيود Wi-Fi only وخيار تنزيل بيانات الهاتف، وتحذير عند عدم كفاية التخزين. طلب الملفات عبر API آمن.

سلامة المحتوى:
- تنزيل إلى مجلد مؤقت staging.
- تحقق SHA-256 والحجم والنسخة والتراخيص ومعايير path traversal.
- تثبيت ناجح للملفات ثم تحديث Room transaction/record؛ استعد التشغيل عند فشل جزئي دون تلف حزمة موجودة.
- تحديث حزمة مختلفة النسخة دون مسح مفضلة أو ملاحظات المستخدم.
- حذف الحزمة اختيارياً وحذف بياناتها المخزنة دون حذف BaseSeed.
- افصل بين ذاكرة الصور العابرة للعرض عبر الإنترنت وبين «تنزيل دائم للعمل دون نت».

إثبات مطلوب داخل هذه المرحلة: نموذج اختبار لحزمة نصية وصورة أصلية صغيرة موجودة في assets أو في Neon إذا وصل الاتصال؛ تشغيل نفس واجهة التنزيل/التثبيت/الحذف، ثم فتحها في وضع الطيران بعد حفظها الدائم. عند وجود Neon فعلي، اختبر حزمة فعلية من Object Storage مع bytes/hash حقيقيين؛ إن لم يوجد، صرّح أن اختبار Cloud→Offline ينتظر نشر Neon، ولا تختلق دليلًا.

احترم قيود عمل Android background عبر WorkManager؛ استمرارية التحميل لا تبرر استنزاف البطارية أو تخزين البيانات خارج مجلد التطبيق. في هذه المرحلة لا تطلب من مستخدم أن ينزل 100–200 ميجابايت تلقائيًا.

بنية provenance: source name، DOI/URL حقيقي، publisher، retrieval date، version/date of science evidence، reuse license، attribution، topic/source relationship، review status و reviewer عندما يوجد بالفعل. افصل «تاريخ استيراد» عن «تاريخ مراجعة بشرية». المحتوى الصحي الحساس لا يُنشر كجرعة أو بروتوكول معتمد إلا بعد اعتماد اختصاصي؛ لا تقدّم المشورة الشخصية ضمن تطبيق تعليمي.

نفّذ اختبارات بقدر ما توفره Google AI Studio، وسجّل Passed/Failed/Not-run مع أدلة:
1. Android Gradle build حقيقي، إصلاح أخطاء imports/dependencies/compilation.
2. Android emulator preview: تشغيل، الرئيسية، التنقل بين الأقسام، فتح تفاصيل، تغيير اللغة، حفظ المفضلة، العودة دون فقد الحالة.
3. First-launch offline: افتح التطبيق والإنترنت مفصول؛ يجب عرض 10–20 عنصرًا seed مباشرة وفهرس بحث محلي.
4. Room migrations/version، عدم تكرار seed في كل فتح، persistence بعد إعادة تشغيل التطبيق.
5. Download unit tests: metadata/manifest parsing، correct hash، wrong hash، missing files، cancel، retry، disk full، network unavailable.
6. Online availability: عند توفر Neon المنشور، استدعِ health/catalog والـmanifest بالإنترنت الحقيقي، ثم تنزيل حزمة واختبرها في وضع الطيران. دون نشر Neon: mark integration blocked لا ناجح.
7. Security: لا API Keys سرية داخل APK أو Gradle/Kotlin resources أو ZIP؛ عدم طباعة أسرار في logs؛ تحقق HTTPS، عدم إظهار unpublished content.
8. AR/EN RTL/LTR: اتساق اتجاه text fields وخطوط وعرض أسماء لاتينية داخل العربية، Dark mode وحجم الخط وسلوك accessibility.
9. اختبر API 26 في المحاكي إذا توفر؛ وإلا أثبت minSdk=26 في manifest/build وأدرج نقص اختبار الجهاز في التقرير.
10. performance sanity: منع ANR في القراءة، والقوائم قابلة للتمرير على هاتف متوسط، عدم تحميل صور ثقيلة دفعة واحدة.
11. إذا أمكن الوصول إلى GitHub Actions خارج Android Build: أضف CI للتحليل والاختبارات وGradle assemble. لا تقل إنه نجح حتى يظهر Run ناجح.
