# المرحلة الثانية — تحميل المجسم الحقيقي وحدود اعتماد المحتوى

تاريخ التدقيق: 24 أكتوبر 2026 بتوقيت اليمن.

## الإصلاح المنفذ

كان التطبيق يحقن ملف GLB بعد 350ms بصرف النظر عن اكتمال الصفحة، ولا يثبت جسر Android الذي تستدعيه JavaScript عند تحديد معلم أو فشل WebGL. وكان العارض يبني أشكالًا إجرائية حتى إن لم يحمل الملف.

أصبح تحميل الملف مرتبطًا بـonPageFinished، مع مطابقة الحجم وSHA-256 للعقد الموجود قبل حقن البيانات. أضيف جسر محدود لأحداث اختيار المعلم ونجاح التحميل والفشل، مع إرسال تغييرات الحالة إلى خيط الواجهة والتحقق من أسماء الأجزاء. يمنع WebView طلبات الشبكة والتنقل الخارجي، ويحرر الموارد ويلغي مهمة القراءة عند الخروج. تعاد إعدادات العزل والشفافية والطبقات بعد اكتمال تحميل الملف أو إعادة إنشاء العارض.

أزيلت الأشكال الإجرائية البديلة من مشهد 3D. لا يصبح المشهد جاهزًا إلا بعد تحليل GLB الحقيقي؛ ترفض رؤوس الملفات وأطوال المقاطع غير الصالحة. فشل WebGL أو shader أو التحليل أو فقد السياق يفعّل البديل ثنائي الأبعاد. المؤشر الذي كان يقول SHA-256 Verified دون إجراء الفحص أصبح يعكس اكتمال التحقق والتحميل.

## أدلة الاختبار

- فحص بناء JavaScript محليًا نجح.
- اختُبر محلل JavaScript على ملف cor_chambers_low_v1.glb الحقيقي باستخدام WebGL وهمي لاختبار مسار التحليل فقط: المشهد الابتدائي فارغ، يحمل ستة meshes، ويرفض الملف التالف ويطلب البديل. هذا ليس اختبار عرض GPU.
- أضيف LocalAnatomyViewerTest لاستخدام LocalAnatomyWebView الإنتاجي في نشاط Android فعلي على المحاكي: انتظار نجاح تحميل الملف المرفق، عدد الأجزاء الستة، وصول اختيار المعلم إلى المضيف، ورفض GLB التالف. نتائج GPU/Android تُؤخذ من CI الخاصة بطلب الدمج، ولا تُستنتج من فحص Node.
- تبقى اختبارات ترحيل Room والحزم والمفضلة من المرحلة الأولى جزءًا من CI.

## ما لا يثبته هذا التغيير

المجسم الموجود توضيحي تعليمي مبسط؛ لا يمثل أطلسًا سريريًا معتمدًا. اختيار الأجزاء يستعمل التقريب الهندسي الموجود في العارض، وليس تحققًا تشريحيًا أو سريريًا مستقلًا. لم نختبر جهاز ARM64 فعليًا أو كل إصدارات WebView أو قياسات الذاكرة تحت الضغط.

يوجد ملف GLB فعلي واحد في المشروع. عقود القلب عالي التفاصيل والرئتين تشير إلى حزم غير متاحة، وتستعمل بصمة SHA-256 للملف الفارغ كقيمة مكانية؛ لا تُعتبر دليل وجود أو ترخيص أو تحقق علمي لأصول فعلية.

في قاعدة appdb المحددة: الأمراض الـ18 والمواد الفعالة الثماني DRAFT، ولا توجد editorial_reviews أو content_packs. يحجب API المسودات بالفعل. أما قيم verified وhumanReviewedAt داخل بعض بيانات Seed فليست بمفردها سجل مراجعة مؤهلًا؛ لم ننشئ مراجعات بشرية أو نبدل حالة النشر السحابية بناءً عليها.

لا يزال إغلاق المرحلة الثانية بالكامل يتطلب تدقيق المحتوى والمصادر والتراخيص من المراجع المختص، وحزمًا منشورة حقيقية ودورة Neon→Android→Room، وتحققًا من سحب المحتوى وتحديثه. مسار /v1/updates الحالي يعيد revision ثابتًا؛ لا نصفه بمزامنة منشورات كاملة.

## حالة المراحل التالية

لم تُعلن المرحلة الثالثة أو الأكاديمية/الإدارة أو الإصدار المستقر مكتملة. لا تُحوّل المسودات إلى منشورات ولا تُنشأ منتجات دوائية محلية أو تواريخ مراجعة أو توقيع إنتاجي افتراضي لإغلاق قائمة. هذا الطلب يضيف إصلاحًا قابلًا للاختبار للعارض فوق إصلاحات المرحلة الأولى المدمجة.
