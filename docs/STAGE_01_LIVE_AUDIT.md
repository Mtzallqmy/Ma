# المرحلة الأولى — إصلاح الاعتمادية والتحقق الفعلي

تاريخ العمل: 24 أكتوبر 2026 (توقيت اليمن).
المستودع: Mtzallqmy/Ma، طلب الدمج: https://github.com/Mtzallqmy/Ma/pull/1

## ما تغير فعليًا

- تمر تنزيلات الحزم السحابية من الواجهة إلى WorkManager مع قيد الشبكة والتخزين وإعادة المحاولة المحدودة للأخطاء العابرة.
- يُثبت التحديث في جيل ملفات مستقل؛ تبقى الملفات المفهرسة السابقة إلى أن تنجح معاملة Room. فشل البصمة أو الحفظ لا يلغي النسخة المثبتة السابقة.
- تُفحص هوية الحزمة والإصدار ومسارات الملفات وتفرد الملفات والأصول والحجم والبصمة قبل الكتابة. يُفحص JSON الدرس قبل استبدال المحتوى المحلي.
- يُحافظ على حالة النسخة المثبتة عند اكتشاف تحديث، وتُمنع مزاحمة عمليات الاكتشاف والتثبيت والحذف داخل المدير.
- ينتقل إلغاء الطلب عبر طبقات Retrofit والتحميل، ويُلغى العمل المجدول عند حذف الحزمة.
- تُحلل عناوين HTTPS بنيويًا وتُرفض بيانات الدخول داخل URL والعناوين غير الصالحة.
- أُصلح حساب مسار مشغل Gradle وخيارات JVM، وأضيف gradle-wrapper.jar الرسمي للإصدار 8.9 بعد مطابقة SHA-256 المنشور من Gradle، وثُبتت بصمة توزيع Gradle في الإعدادات. تستخدم CI الآن ./gradlew وتتحقق من ملف المشغل. لا ندعي أن التطبيق بُني محليًا دون Android SDK.

## الاختبارات

أول نسخة من الإصلاح، commit 988c5ed، اجتازت بالفعل:
https://github.com/Mtzallqmy/Ma/actions/runs/40040710776

- اختبارات JVM، Android Lint، assembleDebug وفحص الأسرار.
- أربعة اختبارات على محاكي Android 8/API26: التنقل الأولي، قاعدة Seed والبحث وحفظ المفضلة وتقدم القراءة بعد إعادة فتح SQLite، تثبيت وحذف حزمة محلية، وحماية النسخة المثبتة عند فساد إعادة التثبيت.

أضيفت بعدها اختبارات ترحيل v1/v2 إلى v3، وإلغاء طلبات السحابة، وحقن فشل معاملة SQLite أثناء استبدال الأصول. نتائج أحدث commit تُسجل بعد انتهاء CI؛ لا تكفي نتيجة commit سابق لإعلانها ناجحة.

اختبار الترحيل يعيد بناء أعمدة الإصدارين القديمين الموثقة من قاعدة v3، ثم يفتح Room مع الترحيلات الحقيقية للتحقق من المخطط الكامل وحفظ البيانات. لا تتوفر في المستودع قواعد مستخدمين قديمة أو ملفات مخطط مصدرة تاريخية؛ لذلك لا نصفه باختبار جميع قواعد المستخدمين القديمة.

## Neon الفعلية

لم تُغير أي بيانات أو صلاحيات أثناء التدقيق.

- المشروع: icy-mode-02911943، الفرع: br-steep-moon-b9kxm3uf، القاعدة: appdb.
- /health: HTTP 200 وpostgresConnected=true.
- /v1/catalog: HTTP 200، عدد المنشورات 23، availablePacks فارغة.
- القاعدة تحتوي 13 جهازًا و10 أعضاء منشورة تأسيسيًا، و18 مرضًا و8 مواد فعالة بحالة DRAFT.
- /v1/diseases و/v1/medications: HTTP 200 مع قوائم فارغة؛ لم تتسرب المسودات.
- POST /v1/catalog: HTTP 405.
- عدد content_packs وeditorial_reviews: صفر.
- طلب RPC دون مصادقة إلى عنوان Data REST المحدد أعاد HTTP 400؛ لم نربطه كتطبيق عام مجهول. التطبيق يستخدم وظيفة HTTPS الخاصة بالفرع نفسه.
- فُحصت ملفات الحزم الثلاث الموجودة في assets محليًا: الحجم وSHA-256 مطابقان لكل ملف.

## حدود الإنجاز والمراحل التالية

هذه إصلاحات واختبارات للمرحلة الأولى، وليست إعلان إكمال المراحل الخمس.

- لا توجد حزمة منشورة في Neon لإثبات دورة تنزيل سحابية كاملة حتى Room؛ التثبيت المختبر يستعمل أصولًا محلية حقيقية مع تعطيل السحابة.
- لم تُختبر أجهزة ARM64 فعلية أو بطء 2G/3G أو انعدام المساحة أو جميع حالات انقطاع العملية. إعادة المحاولة تبدأ الملف من جديد؛ الاستئناف على مستوى البايتات غير منفذ.
- لا يوجد اختبار اعتماد سريري للمجسم أو مراجعة بشرية طبية مثبتة. لا ننشر المسودات أو جرعات حساسة بحجة نجاح الاختبارات البرمجية.
- الأكاديمية وRBAC الفعلي والإصدار المستقر ليست مكتملة؛ لا يصدر v1.0.0 أو APK إنتاجي من هذه المرحلة.
- لم يُنشأ مشروع Vercel؛ استعلام الحساب لم يُظهر فرقًا متاحة، وهذا لا يمنع العمل على تطبيق Android وNeon الحاليين.
