# المرحلة الخامسة: التحقق الكامل والإصدار المستقر
مهمتك إغلاق جميع نواقص 1–4 ثم إنتاج إصدار مستقر موقع للتوزيع بعد تحقق فعلي.
1. دقق latest main + Pull Requests + tags + GitHub Actions مع تحديد ما اكتمل وما لم يكتمل؛ لا تُلغِ أعمال المراحل السابقة ولا تبدّل قاعدة Neon.
2. اختبر تطبيق Kotlin Compose على Android 8/API26، والإصدارات الحديثة، أجهزة ARM64، RTL/EN، الخطوط، dark/light، تدوير الشاشة، الرجوع، بطء الشبكة، Airplane mode، قلة التخزين، فقد الشبكة أثناء تنزيل الملفات، الاستئناف/التحقق والحذف.
3. اختبر سلسلة كاملة Neon DB→Functions→Android→Room Offline للتشريح/الأمراض/الأدوية/الدروس مع نشر وسحب revisions وSHA-256، تحقق من عدم كشف مصادر أو مسودات أو مفاتيح/توقيعات. راقب التخزين والكلفة والحدود.
4. علميًا: اعمل سجل تراخيص/استشهادات حديثة/مراجعات بشرية مع Gate يمنع نشر الجرعات والتحذيرات غير الموثوقة. لا تعتبر محتوى AI-reviewed بديلًا لمختص.
5. أمن وخصوصية: RLS أو حواجز Functions، SSL فقط، اختبارات اختراق مسارات التنزيل، replay، صلاحيات RBAC، منع SQL injection، إخفاء الأسرار والتواقيع، سياسة الخصوصية وتحفظها محليًا حسب المبدأ الأقل جمعًا.
6. بنية البيانات: ترحيلات تراكمية بدون إسقاط بيانات المستخدم، حزمة base offline صغيرة ومهيكلة، المحتوى الثقيل اختياري، تقدير استهلاك البيانات والتخزين، تحميل تقدم/فشل/إعادة.
7. نفذ Gradle lintDebug، testDebugUnitTest، assembleRelease وتحقق من عدم فشل أي خطوة؛ إذا توافر محاكي اختبر connectedAndroidTest API26 وغيرها. تحقق توقيع APK وminSdk/ABI ومعاينة التثبيت والإقلاع.
8. جهز GitHub Actions لتوقيع آمن دائم من Secrets غير مكشوفة (لا تستخدم test key بمثابة release key). اسم النسخة المستقرة v1.0.0، اسم APK Dawa-Hayah-v1.0.0-android8-arm64.apk؛ ارفع Release مع SHA256SUMS.txt وchangelog ونتائج CI وSBOM إن أمكن.
9. إذا فشل اختبار أو لا يوجد مفتاح توقيع دائم أو لم تنته مراجعة طبّية لازمة، لا تنشر على أنه مستقر؛ اذكر العائق الصريح، واصدر نسخة اختبارية مع تسمية صادقة فقط.
10. ادمج PR بعد نجاح الاختبارات، واكتب تقرير تسليم باللغة العربية يشمل روابط GitHub ومصدر Function والتحقق التجريبي ومعلومات التحديث من Beta.
